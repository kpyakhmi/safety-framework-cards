# Frontier Model Forum pitch template

Send to FMF program lead and any known contacts at member labs **after** the
arXiv post is live. The framing positions the spec as input to FMF's existing
standardization track, not as competition.

---

**Subject:** Safety Framework Cards spec — input for FMF's Technical Report Series?

Dear Frontier Model Forum team,

I posted a paper on arXiv today proposing *Safety Framework Cards* — a
machine-readable spec for documenting frontier safety frameworks along six
structural dimensions (risk ontology, capability thresholds, evaluation
methodology, mitigation commitments, governance triggers, revision protocol).

I'm writing because the FMF's 2025 Technical Report Series — the Risk Taxonomy
and Thresholds report, the Cyber Risks report, and the Common Cyber Risks
piece — has been moving toward standardization on the *risk* axis. The
Safety Framework Cards spec is complementary: it standardizes the
*framework-structure* axis. The two are independent and stackable.

The spec ships with:

- A JSON Schema (open-source, MIT-licensed)
- A Python validator + HTML renderer
- Nine reference cards retrofitted from current published frameworks (Anthropic,
  OpenAI, DeepMind, Meta, Amazon, Microsoft, xAI, Mistral, Cohere)

I would value the FMF's reaction to the spec — whether it overlaps with work
already in progress, whether it would be useful as input to a future technical
report, and whether any FMF members would consider publishing official
publisher-verified cards.
